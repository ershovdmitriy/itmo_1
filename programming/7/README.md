## О проекте
**Lab7** - это учебное клиент-серверное приложение для управления коллекцией объектов типа `HumanBeing`.  
Приложение реализует многопользовательский доступ, разграничение прав на основе авторизации, хранение данных в реляционной базе данных PostgreSQL и работу по сети через протокол UDP.

Проект выполнен в рамках курса по программированию на Java и демонстрирует:
- применение **клиент-серверной архитектуры**;
- работу с **сетевыми сокетами (UDP)**;
- использование **многопоточности** для обработки запросов;
- взаимодействие с **базой данных PostgreSQL** через JDBC;
- реализацию **командного интерфейса** с возможностью выполнения скриптов;
- **логирование** на серверной стороне;
- **хеширование паролей** (MD2) для базовой безопасности.

## Архитектура (слои)

Проект разделён на три основных модуля (согласно структуре пакетов):

### 1. **Client** (`lab7.client`)
- **builders** - пошаговое создание объектов (`HumanBeing`, `Coordinates`, `Car`, `WeaponType`) с валидацией ввода.
- **commands** - клиентские команды, реализующие интерфейс `ClientCommand`.  
  Каждая команда умеет:
  - проверять аргументы;
  - формировать `CommandRequest` для отправки на сервер;
  - обрабатывать `CommandResponse` (вывод результата).
- **network** - `UdpClient` с таймаутами и повторными попытками (retry-механизм).
- **Main** - точка входа, запрашивает порт сервера и запускает интерактивную сессию.

### 2. **Common** (`lab7.common`) - разделяемые классы
- **collection** - модель данных (`HumanBeing`, `Coordinates`, `Car`, `WeaponType`) и интерфейс `HavingId`.
- **service** - транспортные объекты `CommandRequest` / `CommandResponse` (сериализуемые) и утилита `Serializer`.
- **validators** - валидация строк (не null, не пустые).
- **exception** - `CommandException` для обработки ошибок выполнения.

### 3. **Server** (`lab7.server`)
- **collections** - менеджеры коллекций:
  - `HumanBeingManager` - хранит коллекцию в `LinkedHashMap<String, HumanBeing>`, синхронизирует с БД, использует `ReadWriteLock` для потокобезопасности.
  - `UserManager` - управление пользователями (проверка, добавление, хеширование пароля).
  - `HumanBeingSqlManager`, `UsersSqlManager`, `MetaSqlManager` - DAO-слой для работы с таблицами PostgreSQL.
- **commands** - серверные команды, реализующие `ServerCommand`.  
  Каждая выполняет бизнес-логику, проверяет права пользователя и возвращает `CommandResponse`.
- **network** - `UdpServer` принимает запросы, создаёт `RequestHandler` для обработки, а `ResponseSender` асинхронно отправляет ответы через пул потоков.
- **logging** - `ServerLogger` пишет логи в консоль и файл с меткой времени.
- **Main** - точка входа сервера: инициализация БД, создание менеджеров, запуск UDP-сервера.

## Структура базы данных (PostgreSQL)

- **users** - `(id, login, password)` – пароль хранится в хешированном виде (MD2 + соль).
- **coordinates** - `(id, x, y)`.
- **cars** - `(id, cool)` – таблица с предопределёнными записями (ссылается по значению `cool`).
- **human_beings** - основная таблица с полями:
  - `key` (уникальный строковый ключ коллекции),
  - `name`, `creation_date`, `real_hero`, `has_toothpick`, `impact_speed`,
  - `soundtrack_name`, `minutes_of_waiting`, `weapon_type` (ENUM),
  - `coordinates_id`, `car_id`, `user_id` (внешние ключи).

- **meta** - хранит тип коллекции (`LinkedHashMap`) и дату инициализации.

## Особенности реализации

- **Сетевое взаимодействие**: UDP с сериализацией объектов, неблокирующий канал на клиенте, блокирующий сокет с таймаутом на сервере.
- **Многопоточность**:
  - На сервере пул потоков для обработки запросов (`REQUEST_POOL_SIZE = 10`) и отдельный пул для отправки ответов (`RESPONSE_POOL_SIZE = 10`).
  - `ReadWriteLock` защищает коллекцию при одновременных изменениях.
- **Безопасность**:
  - Пароли хешируются алгоритмом MD2 с добавлением соли (на клиенте и сервере – разные соли для предотвращения коллизий).
  - Проверка прав: команды модификации выполняются только для элементов, принадлежащих текущему пользователю.
- **Скрипты**: поддерживается `execute_script`; рекурсивные вызовы одного и того же файла игнорируются.
- **Логирование**: все события сервера (запросы, ошибки, старт/стоп) записываются в `server.log` и дублируются в консоль.
- **Консольное управление сервером**: можно ввести `exit` в консоль сервера для graceful shutdown.

##  Запуск

1. **Настройка БД**  
   Создать базу PostgreSQL и выполнить DDL-скрипты (таблицы, последовательности, ENUM).  
   В `Main` сервера указать строку подключения `jdbc:postgresql://localhost:5432/studs` (при необходимости изменить).

2. **Сборка**  
   `mvn clean package` (Maven соберёт `jar`-файлы с зависимостями).

3. **Запуск сервера**  
   `java -jar server.jar` – ввести порт, логин и пароль для БД.

4. **Запуск клиента**  
   `java -jar client.jar` – ввести порт сервера (если сервер на локальной машине, `localhost` по умолчанию).
