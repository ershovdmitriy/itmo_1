## Общая концепция

Проект представляет собой **веб-приложение для проверки попадания точек в заданную область на координатной плоскости**. Пользователь авторизуется, выбирает радиус `R`, вводит координаты `X` и `Y` (либо кликает на график), после чего система определяет, попадает ли точка в закрашенную область, и сохраняет результат в базу данных. Все операции выполняются в рамках сессии пользователя, а история проверок отображается в виде таблицы.

## Стек технологий

### Backend (серверная часть)
- **Java 17** - язык программирования
- **Spring Boot 4.0.2** - основной фреймворк
- **Spring Security** - аутентификация и управление сессиями
- **Spring Data JPA (Hibernate)** - ORM для работы с базой данных
- **PostgreSQL** - реляционная база данных
- **Jakarta Validation** - валидация входных данных
- **Maven** - система сборки
- **Lombok** (не используется, но доступен) - для упрощения кода

### Frontend (клиентская часть)
- **Vue 3 (Composition API)** - прогрессивный JavaScript-фреймворк
- **Axios** - HTTP-клиент для взаимодействия с бэкендом
- **Vite** - быстрый сборщик и dev-сервер
- **HTML5 Canvas** - отрисовка графика и интерактивный ввод точек

### Инфраструктура
- **RESTful API** - взаимодействие между фронтендом и бэкендом
- **CORS** - настройка для работы с локальным фронтенд-сервером (`http://localhost:5173`)
- **HTTP-сессии** - аутентификация через стандартные сессии (без JWT)

## Архитектура и слои

Проект построен по классической **клиент-серверной архитектуре** с разделением на два независимых модуля:

### 1. **Frontend (Vue.js)**
- **Компонентный подход**: каждый элемент интерфейса вынесен в отдельный компонент (`AuthForm`, `GraphCanvas`, `PointForm`, `ResultsTable`, `Header`).
- **Слой представления**: отвечает за отображение данных, взаимодействие с пользователем и отправку HTTP-запросов.
- **Состояние**: управляется реактивными свойствами в корневом компоненте `App.vue`.
- **Обработка ошибок**: централизованное уведомления через всплывающие сообщения.

### 2. **Backend (Spring Boot)**
Приложение построено на **трёхуровневой архитектуре**:

#### 2.1. **Контроллеры (Controller Layer)**
- `AuthController` - регистрация, логин, логаут, получение текущего пользователя.
- `PointController` - добавление, получение и удаление точек для авторизованного пользователя.
- Используют `@RestController` и возвращают JSON-ответы.

#### 2.2. **Сервисы (Service Layer)**
- `AuthService` - бизнес-логика аутентификации (регистрация, проверка пароля, создание сессии).
- `PointCheckService` - логика проверки попадания точки в область (алгоритм на основе координат и радиуса).
- `UserService` — реализация `UserDetailsService` для Spring Security (загрузка пользователя по имени).

#### 2.3. **Репозитории (Repository Layer)**
- `UserRepository` - CRUD-операции с пользователями.
- `PointResultRepository` - операции с результатами проверок точек (привязка к пользователю).

#### 2.4. **Модели (Model Layer)**
- `User` - сущность пользователя с полями: `id`, `username`, `passwordHash`, `createdAt`, список точек.
- `PointResult` - сущность результата проверки: `id`, `x`, `y`, `r`, `hit` (попадание), `executionTime`, `createdAt`, связь с `User`.

#### 2.5. **DTO (Data Transfer Objects)**
- `AuthRequest` / `AuthResponse` - для передачи данных при регистрации/логине.
- `PointRequest` / `PointResponse` - для приёма и отдачи данных о точках.

#### 2.6. **Конфигурация безопасности**
- `SecurityConfig` - настройка Spring Security:
  - Отключение CSRF (для упрощения разработки).
  - Настройка CORS (разрешён только фронтенд-адрес).
  - Разрешение публичного доступа к `/api/auth/register` и `/api/auth/login`.
  - Все остальные запросы требуют аутентификации.
  - Использование сессионной аутентификации (не JWT).
  - Хеширование паролей через `BCryptPasswordEncoder`.

#### 2.7. **Глобальная обработка исключений**
- `GlobalExceptionHandler` - перехватывает ошибки валидации и другие исключения, возвращая читаемый JSON-ответ.

## Взаимодействие между слоями

1. **Пользователь** взаимодействует с интерфейсом (Vue).
2. **Фронтенд** отправляет HTTP-запросы к REST-контроллерам бэкенда.
3. **Контроллер** получает запрос, проверяет аутентификацию (через `@AuthenticationPrincipal`), вызывает нужный **сервис**.
4. **Сервис** выполняет бизнес-логику (регистрация, проверка попадания) и обращается к **репозиторию** для работы с БД.
5. **Репозиторий** (Spring Data JPA) выполняет SQL-запросы и возвращает сущности.
6. **Сервис** преобразует сущности в DTO и возвращает в **контроллер**.
7. **Контроллер** отправляет DTO в виде JSON-ответа на **фронтенд**.
8. **Фронтенд** обновляет состояние и перерисовывает компоненты.

## Особенности реализации

### Алгоритм проверки попадания (метод `checkHit`)
- Область представляет собой комбинацию трёх фигур:
  1. **Прямоугольник** в левом верхнем квадранте (`x ∈ (-R/2; 0), y ∈ (0; R)`).
  2. **Треугольник** в левом нижнем квадранте (неравенство `2x + y + R ≥ 0`).
  3. **Четверть круга** в правом нижнем квадранте (`x² + y² ≤ (R/2)²`).

### Безопасность
- Пароли хранятся в хешированном виде (`BCrypt`).
- Доступ к точкам привязан к конкретному пользователю (через `user_id`).
- Выход из системы аннулирует сессию и очищает контекст безопасности.

### Интерактивный график
- На холсте отображаются оси, сетка, закрашенная область в зависимости от `R`.
- Клик по графику автоматически генерирует координаты точки с округлением до 2 знаков и отправляет запрос на проверку (если выбран `R`).

### Валидация данных
- На бэкенде - через аннотации `@Valid` и `@DecimalMin`/`@DecimalMax`.
- На фронтенде - предварительная проверка перед отправкой.

### Управление состоянием
- Все точки загружаются при входе и обновляются после добавления или удаления.
- Уведомления (успех/ошибка) исчезают через 3 секунды.

## Запуск и настройка

1. **База данных**: PostgreSQL, конфигурация в `application.yaml` (логин/пароль).
2. **Backend**: запуск через `mvn spring-boot:run` или исполняемый JAR.
3. **Frontend**: `npm install` → `npm run dev` (порт 5173).
4. **CORS**: фронтенд должен обращаться к `http://localhost:8080`.
